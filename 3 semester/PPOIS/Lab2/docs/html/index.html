1. Общие сведения о проекте

Проект представляет собой объектно-ориентированную программную модель музейного комплекса мирового уровня. Система комплексно автоматизирует все аспекты музейного дела:

  • Фондовую и экспозиционную работу: каталогизация шедевров живописи, скульптур, рукописей, археологических находок, размещение их в залах и хранилищах;
  • Микроклимат и сохранность: мониторинг температуры, относительной влажности, люксов освещенности через датчики с автоматической термо-регуляцией;
  • Межмузейный обмен и логистику: заключение соглашений о временных выставках с музеями-партнерами (Лувр, Прадо и др.), транспортировка в климатических контейнерах;
  • Экскурсионную и культурную деятельность: планирование временных выставок, формирование маршрутов, назначение гидов, выдача аудиогидов;
  • Работу с посетителями: продажа билетов с динамическими льготными тарифами (студенты, пенсионеры), годовые абонементы, гардеробные номерки и отзывы;
  • Научно-реставрационную лабораторию: составление актов дефектации (Condition Report), списание реставрационных материалов, завершение циклов реставрации;
  • Комплексную безопасность: видеонаблюдение, датчики вибрации/периметра, доступ по ключ-картам, протоколирование инцидентов и тревог;
  • Финансовый менеджмент и сувенирный магазин: контроль сводного бюджета, поступление грантов и донатов, продажа сувениров через кассовые терминалы.

5. Реализация ключевых принципов ООП и паттернов проектирования

1. Инкапсуляция

Все 259 полей данных во всех классах объявлены как private либо protected. Прямой доступ к внутреннему состоянию запрещен. Доступ и модификация производятся исключительно через геттеры и семантические методы, валидирующие инварианты (проверка неотрицательности цен, допустимости габаритов, диапазонов дат и корректности прав доступа).

2. Наследование (Иерархии)

В проекте представлены две разветвленные иерархии предметной области и одна иерархия ошибок:

  • Иерархия экспонатов: базовый Artifact → Painting, Sculpture, AncientManuscript, ArcheologicalFind.
  • Иерархия персонала: базовый Employee → Curator, TourGuide, Restorer, SecurityGuard.
  • Иерархия исключений: базовый std::exception → MuseumException → 12 специализированных классов.

3. Полиморфизм

Используется динамический полиморфизм времени выполнения через механизм виртуальных таблиц (vtable):

  • Виртуальный метод Artifact::calculateImportanceScore() const переопределяется (override) в каждом подклассе экспонатов, учитывая специфику (слой лака и тип красок у картин, вес и постамент у скульптур, древность рукописи, радиоуглеродный возраст артефакта).
  • Виртуальный метод Employee::calculateMonthlySalary() const переопределяется для кураторов (надбавка за число выставок), гидов (за количество экскурсий), реставраторов (за квалификационную категорию) и охраны (за ночные смены и оружие).
  • Виртуальные деструкторы объявлены во всех базовых классах для предотвращения утечек памяти при полиморфном удалении через указатели на базовый тип.

4. Композиция и Агрегация

Класс ExhibitionHall владеет датчиками ClimateSensor и ClimateControlUnit на правах композиции (их жизненный цикл неразрывно связан с залом). Класс CollectionCatalog и HRDepartment агрегируют умные указатели на экспонаты и сотрудников, управляя их жизненным циклом и ассоциациями.

5. Паттерны проектирования

  • Facade (Фасад): Класс Museum скрывает сложность 52 классов системы за простым и интуитивным высокоуровневым интерфейсом (acquireArtifact, admitVisitor, openMuseum, runNightAudit).
  • Strategy (Стратегия): Класс DiscountPolicy инкапсулирует алгоритмы вычисления льготных тарифов для разных социальных групп посетителей.
  • RAII (Resource Acquisition Is Initialization): Безопасное управление ресурсами и памятью без утечек и висячих указателей.

8. Руководство по сборке и запуску

Проект компилируется с использованием CMake и любого компилятора C++17 (MSVC 2019/2022/2026, GCC 9+, Clang 10+).

Сборка на Windows (PowerShell):

# 1. Перейдите в корневую директорию проекта:
cd "C:\Users\Рома\Desktop\Универ\ППОИС\Lab2"

# 2. Сгенерируйте решение CMake (создаст папку build):
cmake -S . -B build

# 3. Скомпилируйте проект в конфигурации Release:
cmake --build build --config Release

# 4. Запустите модульные тесты:
.\build\Release\museum_tests.exe

# 5. Запустите интерактивную консольную программу:
.\build\Release\museum_app.exe

Сборка на Linux / macOS:

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/museum_tests
./build/museum_app
Важное примечание: Команда генерации cmake -S . -B build выполняется первой, чтобы сформировать файлы сборки. Только после этого запускается компиляция cmake --build build.
