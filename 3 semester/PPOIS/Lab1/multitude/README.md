# Лабораторная работа №1: Неориентированное канторовское множество (`CantorSet`)

Реализация лабораторной работы №1 по курсу **«Проектирование программного обеспечения интеллектуальных систем» (ППОИС)** на языке **C++ (C++17)**.  
**Вариант:** `1.4 Теория множеств` / `1.4.1 Множество (Неориентированное канторовское множество)`.

## Реализованные возможности

Класс `CantorSet` (`include/CantorSet.h`, `src/CantorSet.cpp`) реализует математическое неориентированное канторовское множество (элементы не повторяются и не упорядочены):

- **Произвольная глубина вложенности**: элементом множества может быть как атомарная строка (`a`, `b`, `c`), так и другое множество (`{a, b}`, `{}`, `{a, {c}}`).
- **Формирование из строки**: поддержка как `std::string`, так и `const char*` (например: `"{a, b, c, {a, b}, {}, {a, {c}}}"`).
- **Проверка на пустое множество**: `isEmpty() const`.
- **Определение мощности множества**: `cardinality() const`.
- **Добавление и удаление элементов**: перегруженные методы `add(...)` и `remove(...)` для `std::string`, `const char*` и вложенного `CantorSet`.
- **Проверка принадлежности элемента (`operator[]` и `contains`)**: `set["a"]`, `set[CantorSet("{a, b}")]`.
- **Теоретико-множественные операции**:
  - Объединение двух множеств: `operator+` и `operator+=`;
  - Пересечение двух множеств: `operator*` и `operator*=`;
  - Разность двух множеств: `operator-` и `operator-=`;
  - Построение булеана P(A) (множества всех 2^n подмножеств): `powerSet() const`.
- **Операции сравнения**:
  - Проверка на равенство и неравенство (независимо от порядка элементов): `operator==`, `operator!=`;
  - Проверка включения подмножества/надмножества: `operator<=`, `operator<`, `operator>=`, `operator>`.
- **Потоковый ввод и вывод**: дружественные операторы `operator<<` и `operator>>`.
- **Требования C++ ООП**:
  - Инкапсуляция и разделение интерфейса (`include/CantorSet.h`) и реализации (`src/CantorSet.cpp`);
  - Динамическое управление памятью (`new` / `delete`) и правило трёх (конструктор копирования, `operator=`, деструктор);
  - Использование `const`, указателя `this`, ссылок `&` и спецификатора `mutable` (кэширование строкового представления в `toString() const`);
  - Определение методов внутри и вне класса, статические методы (`fromString`, `isValidSetString`).

## Ответы на контрольные вопросы из методички (раздел 3)

1. **Зачем использовать ссылки `const T&` при передаче аргументов?**  
   Передача объекта по значению вызывает конструктор копирования, что для `CantorSet` приводит к глубокому копированию динамического массива и всех вложенных множеств. Передача по константной ссылке (`const CantorSet&`, `const std::string&`) избегает накладных расходов на копирование и защищает исходный объект от изменения внутри метода.
2. **В чём разница между операторами `+` и `+=` (и их возвращаемыми типами)?**  
   Оператор `+=` изменяет левый операнд на месте и возвращает ссылку на себя (`CantorSet&`, т. е. `*this`), не создавая лишней временной копии при возврате. Оператор `+` не изменяет исходные операнды (объявлен как `const`), создаёт новый объект-результат и возвращает его по значению (`CantorSet`).
3. **В каких случаях нужен пользовательский конструктор копирования?**  
   Конструктор копирования (вместе с деструктором и оператором присваивания `=` — «правило трёх») необходим, когда класс владеет ресурсами, выделенными динамически (через `new` / `new[]`). Стандартный (сгенерированный компилятором) конструктор копирования выполняет поверхностное (побитовое) копирование указателей (`elements_`, `subset`), что привело бы к разделению одной и той же памяти между двумя объектами и двойному освобождению (`double free`) при вызове деструкторов.
4. **Зачем нужен спецификатор `mutable`?**  
   Поля `cachedString_` и `isCacheValid_` объявлены как `mutable`, чтобы константный метод `toString() const` (и оператор `<<`) мог кэшировать сформированное строковое представление множества при первом вызове, не нарушая логическую константность объекта `CantorSet`.
